Disk Explorer, but PS2 Save File

A disk-usage analyzer that presents drives as memory cards and folders as animated save icons. Delete one and it plays its own death animation — because on the PS2, it always did.

Corrected from screenshots

The browser is silver, not blue

Nearly every written source describes the PS2's system UI as dark blue. That's the boot screen. The Browser — the part with your saves in it — sits on a light silver-grey ground with soft concentric ripples, and the grid view is a smooth grey gradient lit from one side. Getting this wrong makes everything downstream feel like a different console.

Selection

A light, not a box

The highlighted icon has a hard specular bloom behind it — an actual light source in the scene. No cursor, no border, no fill. That bloom is the entire selection affordance.

Typography

Gold, top right

The selected save's name is set large in a saturated golden yellow, right-aligned in the top corner. Card name and free space sit opposite it in white. Everything carries a soft drop shadow so it survives on any backdrop.

Options

A real focus pull

Opening Copy/Delete defocuses every other icon and holds the selected one sharp. Not a dim overlay — a depth-of-field blur, with the background already repainted in that save's own colors.

Free space

Counted in KB

2,138 KB Free, comma-grouped, directly under the card name. Carried over literally, a modern drive reads 1,952,741,376 KB Free — absurd, and worth keeping.

The mechanic

Three icons per save

Each save's metadata names three separate model files: one for browsing, one that plays while it's being copied, and one that plays while it's being deleted.

Most studios shipped the same model three times. The ones who cared made the delete animation the character dissolving, exploding, or waving goodbye — a small farewell nobody was obligated to build.

That's the pitch. A disk cleaner where the folder you're about to delete visibly reacts is a thing nobody has made, and the format that inspired it hands you the structure for free. Open Options → Delete up top.

Why they look like that

The constraints are the art style

Unforgiving in ways that turn out to be a gift: they make hand-authoring a full icon set realistic for one person.

Geometry

~500 triangles

A raw, non-indexed triangle list. No index buffer, no skeleton.

Texture

128 × 128, 16-bit

A1B5G5R5 — one alpha bit, five bits per channel, optionally RLE-compressed.

Animation

Vertex morphing

Whole-mesh snapshots called shapes, blended by a tween factor. Exactly glTF morph targets.

Lighting

Three lights + ambient

Stored per save. (ambient + Σ max(dot(N,L),0)) × texture. That's the whole shader.

Look at the reference grid: a rock, a skateboard, a soda can, a Sonic head, a dragon, two golf balls. No house style, no size rule, no shared silhouette — every studio interpreted the box differently, and the resulting jumble is most of the charm. Normals also don't morph with position, so deforming icons light slightly wrong. Keep that bug; it's free character.

Two deliberate departures. Sort by size, descending — the PS2 didn't sort, but "what's eating my disk" is the whole job. And caption every icon with its size, which the original never needed to do.

Build

A Rust scanner and a WebGL face

Scanner · Rust

Read the MFT, not the tree

On NTFS the Master File Table already holds every name, size and parent reference — parse it and rebuild the tree in memory instead of walking directories. This is how WizTree scans a terabyte in seconds. Needs Administrator, so ship a threaded FindFirstFileEx fallback and sell speed as an opt-in rather than a UAC wall at launch.

UI · Tauri v2 + WebGL

The Rust core is already there

Morph targets, per-save gradients and bloom are one-liners in a web stack, and the scanner becomes a command in the same binary. Ships at a few MB. Electron if you want byte-identical Chromium; Godot 4 if you'd rather live in an engine, but the scanner is Rust either way.

Look

Point-sample everything

No texture filtering. Render at ~640×448 and upscale. Subtle vertex snapping, because PS2 fixed-point math made geometry shimmer. Skip affine texture warping — that's PS1, and getting it wrong is the tell.

Assets

Blender → glTF shape keys

glTF morph targets map onto PS2 shapes one-to-one. Three clips per icon: idle, copy, delete. Roughly thirty icons covers a drive.

The BIOS font is a bitmap font in ROM (rom0:FONTM) and the BIOS audio is Sony's — don't ship either. A lookalike face plus a synthesized blip carries the atmosphere. Same rule for the well-known Shadertoy PS2 background: read it for technique, write your own, it's CC BY-NC-SA.

The feature that sells it

Import a real memory card

Let people drop in an actual .ps2 card image, .psu, or .max save and use those icons for their folders. The parsers are open source and PS2IODB is a ready-made asset library for anyone without a card in a drawer. node_modules rendered as a save icon from a 2003 platformer is the screenshot that makes this spread. Ship the parser, not the assets.

Traps

What makes disk analyzers wrong

  • Logical size vs size on disk. Round to cluster size or the totals drift.
  • Hardlinks. Dedupe by file ID or you count the same bytes repeatedly.
  • Sparse files. A 1 GB sparse file can occupy 64 KB.
  • Reparse points, junctions, symlinks. Don't follow, don't double-count.
  • Cloud placeholders. OneDrive and iCloud files that aren't local — touching them can trigger multi-gigabyte downloads.
  • Long paths. Use the \\?\ prefix or enable long-path support.
  • This app deletes files. Recycle Bin by default, explicit confirmation — the PS2 asked too — system paths hard-blocked, and the delete animation never starts before the operation is authorized.
  • Scale mismatch. An 8 MB card held about thirty saves. A 2 TB drive holds millions of files.
